## 기능 반영 검증 (실행 → 결과가 실제로 반영되는지)

| 범위 | 방법 | 결과 |

| 기존 시나리오 | 대화·조리·운동·기록 전체 흐름, 트레이너·건강·나만의 루틴 흐름 | 오류 0건 |

이 검증에서 고친 문제
- 식사 사진의 요리 이름(김치찌개 등)이 영양 참조(재료)에 없어 하루 합계 전체가 비던 문제 → 레시피·재료·추정 주재료 순으로 계산하고, 모르는 음식은 합계에서 빼고 "N건 미확인"으로 표시. 국·찌개는 레시피의 물까지 1인분 무게로 계산
- 사진 후보의 음식 이름을 고칠 수 없던 문제, 저장 후 기록 화면으로 이동해 결과 안내
- 오늘 먹은 것 목록과 섭취 삭제가 없던 문제
- 조리 모드에서 "조리 완료 기록"이 보고 있던 레시피가 아니라 오늘 추천 메뉴로 기록되던 문제
- 예시 재료 수가 화면 문구(18가지)와 실제(21가지)가 다르던 문제
- 휴대폰 하단 메뉴에 화면 맨 아래 버튼이 가리던 문제, 이미 선택된 운동 조건을 다시 눌렀을 때 아무 안내가 없던 문제
- 앱을 켜는 중(레시피·운동 목록을 받기 전)에 탭을 누르면 화면 오류가 나던 문제 → 목록을 받은 뒤에 그린다
- 시간·버티기 운동(스텝 터치, 플랭크 등)에서도 "내려가요"라고 안내하던 문제 → "40초 동안 이어가요 / 버텨요"

키가 필요한 실제 외부 호출(GMS 사진 인식·답변, 식약처 레시피 사진, YouTube)은 같은 형태의 고정 응답으로 검증했다. 실제 키로 한 번 더 확인해야 한다.

## 역할 분리 실험

옛 커밋과 현재 구현에 같은 검색 실패를 입력했다. 응답을 개선할 수 있는 단어 보정은 Worker만 시도한다. 모델·제공처 응답 모두 고정했으며 5회 중앙값이다.

| 모드 | Tool 호출 | 모델 판단 | 재계획 | 대안 상세 확보 | 중앙값 |
|---|---:|---:|---:|---|---:|
| 변경 전 01d54bc | 3 | 0 | 0 | 아니요 | 2.4ms |
| 현재 · Worker LLM 끔 | 3 | 0 | 0 | 아니요 | 2.9ms |
| 현재 · Worker LLM 켬 | 5 | 1 | 0 | 예 | 3.6ms |

이 사례에서는 Worker가 검색어 한 개를 보정해 도구 호출을 두 번 더 사용하고 상세 결과를 얻었다. 모델 활성화가 실서비스 전반의 정확도나 대기시간을 개선하는지는 이 실험만으로 판단할 수 없다.

## 데이터 분석가 포트폴리오

**질문** · 이름만 비교할 때 “만들 수 있다”고 잘못 안내하는 경우를 포장 단위로 줄일 수 있는가?

**비교** · 빈 재고, 1g 부족, 기한 경과, 미계량, 복수 포장, 다인분 등 정답을 수기로 지정한 10개 경계 사례에서 이름 기준은 5개, 포장 기준은 10개를 맞혔다. [사례별 정답과 결과](evidence/inventory-comparison.json)

**다음에 측정할 지표** · 동의한 테스트 사용자에게 추천 후 실제 조리 여부를 기록한다. 조리 전환율의 분모는 중복을 제거한 추천 노출, 분자는 해당 추천에서 완료한 조리다. 현재 앱에서 기록한 조리 건수와 예상 대비 실제 조리시간 절대오차 평균을 확인할 수 있다. 기한 경과 재료를 제외한 횟수와 실제 폐기량은 다른 지표이며, 절감량은 폐기 기록을 수집한 뒤 산출해야 한다.

개인 건강 상태 변화나 체중 감량 효과는 이 평가가 측정한 항목에 포함하지 않았다.

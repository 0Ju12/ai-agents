# 요구사항과 검증 추적표

한끼의 결과물은 포장 재고, 1인분 조리 계획과 필요한 장보기 목록, 운동 루틴, 하루 섭취·생활 기록 및 저장 일정이다. 식품·운동은 독립 도메인 모듈로 두고 대화, 도구 호출, 로깅의 공통 흐름을 공유한다. 교육 자료 원문과 개인 포트폴리오 파일은 저장소에 포함하지 않았다.

| 번호 | 동작과 확인 방법 |
|---|---|
| F3001 | 등록 도구의 이름·종류·인자·응답·오류를 /api/tools 에서 확인한다. |
| F3002 | TheMealDB가 재료로 후보 ID와 제목을 준다. 날짜가 없는 카탈로그의 현재 조회 결과로 최대 4개를 검사한다. |
| F3003 | 앞 단계 ID로 상세 조리법과 재료를 읽어 재고와 비교한다. 영문 재료 일치와 미확인 재료를 표시한다. |
| F3004 | 별도 제공처에서 식재료 영양·바코드·지역 헬스장·쇼핑을 조회한다. 결과 없음, 설정 누락, 직접 검색 링크를 구분한다. |
| F3005 | 자유 입력 또는 명령에서 목표·부위·시간·기준일·시각·지역·예산을 추출한다. 정보가 부족하면 확인을 요청한다. |
| F3006 | Planner가 Task 목록과 순서를 발행한다. 핵심 작업은 규칙으로 정하고, 자연어 요청이면 GMS Claude 모델이 도구 명함 목록을 보고 구조화 출력 `Plan`으로 보조 도구를 고른다. 등록되지 않은 도구·중복은 코드가 버리고, 모델 실패 시 규칙 계획만 쓴다. 사용법과 입력 확인 요청은 도구 없이 응답한다. [테스트](../test_planner.py) |
| F3007 | Worker가 순서대로 실행한다. 상세 ID 전달, 레시피 결과의 재고 부족 재료를 쇼핑 입력(`$부족재료`)으로 넘기기, 요청 내 재사용, 출처별 부분 실패를 포함한다. |
| F3008 | 수량·소비기한·부족 g·영양·시간·표기가격을 비교한다. 예정 일정 전 남는 분과 늦어도 조리를 시작할 시각을 계산한다. |
| F3009 | 후보 상세가 없거나 재료가 맞지 않으면 같은 후보 목록에서 다음 ID로 이동한다. 최초 1회와 최대 재계획 3회를 구분한다. |
| F3010 | 소유 공간·세션별 상태와 마지막 메뉴/재료를 저장한다. 변경 요청의 필드만 갱신한다. |
| F3011 | 추천 분량과 영양 출처, 재료 미확인, 제외 이유, 생활 참고 안내를 확인한다. 자연어 요청은 확인된 결과 값만으로 모델이 `답변` 문장을 만든다(값 생성 금지, 실패 시 구조화 결과만). |
| F3012 | 분석·계획·실행·판정·응답과 도구 인자, 결과 상태, 지연, 판단 방법, 재계획 사유, 실행 ID를 기록한다. |
| F3013 | EventBus → LoggingAgent → Store 구독 방식이다. 기록 자체는 모델을 호출하지 않는다. 구독자 오류는 대화를 막지 않는다. |
| F3014 | /api/logs 에서 세션 목록을, 상세 경로에서 실행 순서를 조회·삭제한다. 수정 경로는 제공하지 않는다. |
| F3015 | 계획의 날짜·시각과 항목을 저장하고 같은 날짜에 겹치는 기존 계획을 반환한다. |
| F3016 | 세부 조회·부분 변경·삭제와 수정 후 남은 중복 여부를 화면에 표시한다. 날짜와 시작·종료 순서를 검증한다. |
| F3017 | FastAPI와 Pydantic, 대화/상태, 계획, 로그, 도구, 캘린더 API를 분리했다. |
| F3018 | 모바일 웹과 Android에서 같은 API를 사용한다. 대화 입력과 일정 관리 화면에서 입력·조회·수정한다. |
| F3019 | 요청 중 상태, 호출 순서, 재계획, 기관 키 누락과 실패 사유를 표시한다. |
| F3020 | 수집 이벤트로 중복 호출, 계획 밖 호출, 같은 도구의 연속 실패, 재계획 상한 도달을 판정한다. 근거 없음과 정상·경고를 구분하고 경고일 때만 모델 진단을 따로 남긴다. |
| F3021 | Task/WorkerResult 계약, 변경 가능한 인자에 한한 제한 재시도, 고정 인자 보호, 검증 경고에 따른 작업 수정과 전후 비교를 제공한다. |
| F3022 | 한끼 안내 문서 31편(영양 섭취기준·식품 안전·운동·생활, 출처 링크 포함)을 Chroma `hankki_guides` 컬렉션에 색인한다. 외부 API로 확인할 수 없는 상식 질문이면 `knowledge` 도구를 선택하고, 근거 문단·출처·거리를 응답에 싣는다. 색인 실패는 NO_INDEX, 관련 근거가 없으면 NO_RESULT. 임베딩은 키 없이 동작하는 글자 조각 해시가 기본이고 `RAG_EMBED=model`이면 모델 임베딩. [테스트](../test_rag.py) |
| F3023 | 날짜 조회 또는 저장 계획 ID 등록이라는 공통 계약으로 로컬/Google 캘린더를 교체한다. 일정 충돌을 추천시간에 반영한다. |
| NF3001 | GMS와 공급자 키는 서버 환경에 설정한다. 앱·저장소에 발급키를 포함하지 않는다. |
| NF3002 | 공급자 URL에 포함한 키와 원문 예외를 사용자 응답·실행 로그에서 제외한다. |
| NF3003 | 도구별 오류를 구조화하고 가능한 부분 응답과 링크를 남긴다. |
| NF3004 | Planner 재계획 3회, Worker 동일 도구의 보정 시도 1회로 제한한다. |
| NF3005 | 외부 통신 타임아웃과 요청별 작업 시작 한도를 둔다. 시나리오와 공개 도구의 측정 지연을 검증 기록에 포함했다. |
| NF3006 | 화면·도메인·저장소·연결 도구·Planner/Worker·로깅을 분리한다. |
| NF3007 | API 표시 출처, 호출 제한·약관, 생성 이미지와 운동 참조 라이선스를 데이터 문서에 기록했다. |

## 증거와 제출 점검

| 항목 | 결과와 근거 |
|---|---|
| 4.1 도구 | 공개 제공처 4곳에서 후보·상세·바코드·영양·운동을 호출했다. [실측](evidence/live-apis.json) |
| 4.2 메인 에이전트 | 정상, 재계획, 상한, 키 누락, 도구 생략, 시간 제약을 고정 자료에서 재현했다. [기대값/실제값](evidence/scenarios.json) |
| 4.3 실행 이력 | 요청 한 건 전체와 후보 교체 이벤트를 보존했다. [전체 이벤트](evidence/one-run.json) |
| 4.4 계획 | 기간 검증, 겹침 경고, 수정·삭제, 일정을 반영한 조리시간 역산을 통합 테스트했다. [테스트](../test_final.py) |
| 4.5 화면 | 브라우저에서 재료 입고 → 조리 → 섭취 → 기록을 조작했다. [화면 캡처](../screens) |
| 4.6 심화 | Worker on/off와 이전 커밋, 원인 진단 분리, 실제 Chroma 시험 인덱스, Google 응답 매핑과 로컬 일정 대조. [역할 비교](evidence/roles-comparison.json) |
| 4.7 대표 시나리오 | 위 6개 각 요청에 기대 동작, 결과, 호출 수, 재계획, 처리 시간을 남겼다. |
| 4.8 비기능 | 소유 공간 분리, 중복 요청, 개별 API 장애, 실제 공개 API와 측정 지연, 빌드·공급자 조건을 점검했다. |
| 3일차 오후 공식 셀프 체크리스트 | 첨부 실습에서 번호가 명시된 1·15·25번과 수업 단계별 결과를 [실행 점검표](course-check.md)에 기록했다. 공식 25개 항목 전체 양식은 제공 자료에서 확인되지 않았다. |

교육 제출 시스템으로의 제출과 Play Store 등록은 각각 계정에서 진행하는 별도 절차다.
